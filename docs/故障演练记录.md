### 为什么「仅表头」是 succeeded 而不是 failed

表头齐全 = 文件格式合法；没有数据行只是「没东西可查」。系统完成了检查、结论是「0 行、0 个问题」，这是**业务结果**，不是**系统错误**。
- `failed` 留给「检查没法做完」：文件读不到、缺必需列。
- `succeeded` 表示「检查做完了」，结果好坏看 summary。

## 发现

1. **缺列和坏路径停在不同阶段**：坏路径在「读文件」就失败，但 `rules_version` 已记上；缺列在「检查列」失败，`rules_version` 为 null。两种失败记录的字段不一致，以后排查要知道这一点（可考虑统一）。
2. **时间是 UTC 且不带时区**：`created_at` 比北京时间慢 8 小时，接口也没标时区，容易误读。
3. **dataset 创建时不检查文件**：坏路径的 dataset 能建成功，要到建 run 才报错。
4. **操作踩坑**：run id 和 dataset id 是两套编号，容易填混（今天 run 68 就误用了 dataset 67）。
